There are major 2 scopes for a bean
#### 1. Singleton(default)(will make one object per bean definition(`1class`=`1defination`))
if have class A and B which need order service as dependency then,![[Pasted image 20260710195215.png]]
as dependency also the same object reference is passed.
this is not related to low level design of singleton(which is strict to create only 1 object of a class), it is more flexible allows more object if have more definition or can create manually using `new`.
```java
public class AppConfig {
    @Bean
    public OrderService getOrderService1(){
        return new OrderService();
    }
    @Bean
    public OrderService getOrderService2(){
        return new OrderService();
    }
    @Bean
    public OrderService getOrderService3(){
        return new OrderService();
    }
} // creates 4 objects
```
on using will need to use primary/qualifier to one(as multiple options)
#### 2. Prototype(creates object every time)
```java
@Component
@Scope("prototype")
public class OrderService {
    OrderService(){
```
now will create new bean for every get and dependency
output changes to 
```bash
Created orderService 
Created orderService 
Order placed successfully
Order placed successfully
```
IOC not fully handles this duplicates.
as IOC will not create object automatically it will be created on demand.(can prove my make order service independent of anything and singleton it will be created by IOC automatically but when in prototype it will not be created unless required).
prototype -> lazy initialization.
singleton -> eager initialization.
#### When what
Singleton -> for stateless class(e.g `Service`,`Manager`)
Prototype -> for state-full class(e.g `User`)

Other scope -> Request(new object for new HTTP request ,Session(new object for new user),Application(new object for new application).

#### Beans initialization
- Eager(default) : creates when IOC starts.
- Lazy(`@Lazy`) : creates when need.
```java
@Component
@Scope("singleton")
@Lazy
public class PaymentSevice(){
```
will create only when need(but only 1 will be created as singleton).
Singleton -> can be eager or lazy
Prototype -> default lazy can't change to eager, because why to make object when need and also partially handled by IOC.

If something is Lazy and something eager need it as dependency will it be created ? --> YES.

can also do lazy for dependency => proxy(wire it to proxy of dependency not actual as it is lazy)
```java
@Component
public class OrderService {

    PaymentService paymentService;

    public OrderService(@Lazy PaymentService paymentService) {
        this.paymentService = paymentService;
        System.out.println("OrderService created");
    }
}
```
> [!Fake it till you make it]
> Proxy -> is a design object which will behave like the dependency but is not actually it.
will create the actual object when it will be needed.

when a method needed that object will be called then, object will be created.
Spring core logic behind this lazy
- if create everything at startup will make initial load very long
- spring default to eager => so fail fast(as if not create bean how will get error in them) thus spring suggest eager in development.
- if sure no error then, only make it lazy.
property: `spring.main.lazy-initialization = true` change default to lazy instead of eager.(default is false)
if need to make class not lazy then, annotation `@Lazy(value=false)`

Circular dependency(constructor) can be solved using Lazy.
