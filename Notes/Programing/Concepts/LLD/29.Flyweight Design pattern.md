It is a problem specific => for saving RAM.
When solving a problem ask is RAM important resource.
then, use this design pattern to save size of objects.
not all object can be using Flyweight.
## Flyweight design pattern
Use case => 
if have many small object many many which fills the RAM ![[Pasted image 20261109183122.png]]
thus, here need to save memory using flyweight design pattern.
find cluster of objects which can be reused.
![[Pasted image 20261109183245.png]]
### Example
For a game which has space-ship and asteroid(millions in number).
![[Pasted image 20261109183700.png]]
based on difficulty no of asteroid keeps on changing.
it is infinite runner => but RAM is finite so, need to re-use this asteroids.
Asteroid class => ![[Pasted image 20261109190832.png]]
size of object = sum of all variables. also there are millions of such object
this is too much memory.
solve => divide the object properties into 2 parts ![[Pasted image 20261109191411.png]] 
- intrinsic => length(10,20,30), width(10,20,30), weight(1,2,3), color(red, blue, green), texture(soft, hard, metal) have limited set of possible values.
- extrinsic => `positionX` and `positionY` can take any number of possible values.
make intrinsic properties re-use-able.
![[Pasted image 20261109194156.png]]
if 10 million = 3 million + 3 million + 4 million
extrinsic property(call context object) should be kept outside and use the intrinsic property(call flyweight object) object again and again.
