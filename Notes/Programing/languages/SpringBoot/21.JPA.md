@ManyToOne

private Department department;

## N+1 problem
for lazy loading -> when fetch many data at one and ask for there loops of loops of queries ![[Pasted image 20260822124549.png]]
query ordering ![[Pasted image 20260822124828.png]]
this is called N+1 query, load increased on DB.
thus, we think we run 1 query but it actually does N+1 query.
solution
- It is mostly solved by L1 cache -> if all 100 student in some 3 department then it is will run only 1+3 query.![[Pasted image 20260822125354.png]]
- This is not fault of lazy loading as if did eagar loading they will have 1 very long query.
Thus, try to avoid N+1 problem -> Lazy is good get it when needed.
Solution -> Entity graph
make thinks of direct use eager initailize and things rarely used Lazy initialize.
```java
    @EntityGraph(attributePaths = "department") // department bring eager
    public Student findById(Long id) {
        return entityManager.find(Student.class, id);
    }
```
or use it in
```java
    @EntityGraph(attributePaths = {"department","profile"})
    public List<Student> findAll() {
        return entityManager.createQuery("from Student").getResultList();
    }
```
