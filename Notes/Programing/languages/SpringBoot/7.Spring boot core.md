#### `@SpringBootApplication`
- has many annotation used internally => configuration![[Pasted image 20260713182504.png]]![[Pasted image 20260713182741.png]]
- can make more config files but spring declares main config file.
- main class is also a config file can make beans in it.
- Thus it scans for `@Component` class to handle.
```java
@SpringBootApplication
public class SpringBootCoreApplication {
    public static void main(String[] args) {
        ApplicationContext context=SpringApplication.run(SpringBootCoreApplication.class, args);
        OrderService os=context.getBean(OrderService.class);
        os.processOrder();
        UserService us=context.getBean(UserService.class);
    }
    @Bean
    public UserService getUserService(){
        return new UserService();
    }
}
```
conventions of spring boot(opinionated frame work)
- component scan happens in the package in which main(spring application class) class is present. can base it `@SpringBootApplication(scanBasePackage="in.strikes")`
- similarly can change config which you don't agree to by passing value for key.
#### `@EnableAutoConfiguration`
see project and create all important beans based on current project structure.
"Look at my project and create any beans seem important to you."
same methods
- `@Component` -> to make bean of a class
- `@Bean` -> to make a method bean
there is a third way
- `@AutoConfiguration` -> it used internally by spring boot. for special class made by spring boot inside it make beans.
for this third way to work need to enable it using this config `@EnableAutoConfiguration`.
similarly can make more beans
```java
@SpringBootApplication
public class SpringBootCoreApplication {
    public static void main(String[] args) {
        ApplicationContext context=SpringApplication.run(SpringBootCoreApplication.class, args);
        OrderService os=context.getBean(OrderService.class);
        os.processOrder();
        UserService us=context.getBean(UserService.class);
    }
    @Bean
    public UserService getUserService(){
        return new UserService();
    }
    @Bean
    public JsonParser getJsonParser(){
        return new BasicJsonParser();
    }
}
```
generally will do it for own jar instead of `JsonParser`
all external library jar file bean are not created directly then,
- if spring need some from it(if have many dependency)
- show to connect many classes need to do many manual config
- spring has some classes to manage this dependency. which will get this `@AutoConfiguration`
- example can get use of web starter => to make 
```xml
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
```
at run it will start a server at `Tomcat initialized with port 8080 (http)`
will have some class whose being in IOC is important thus, it will be handle by spring using `@AutoConfiguration`.
thus background works -> starts server.
- It is written in spring for web(standard library) OR
- if other dependency they may also have it(non-standard).
```java
@AutoConfiguration
@ConditionalOnClass(getWebA.class)
class A{
	@Bean
	@ConditionalOnMissingBean // create if not already exist
	public WebClassA getwebclassA(){
		return new WebClassA();
	}
}
```
will make bean if condition class exists in dependency.
will have auto config by using this annotation.
