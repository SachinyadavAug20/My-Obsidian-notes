### Operation CRDTs
using distributed counter.

- Disadvantage => causal relationships

### State-based CRDTs
send the whole CRDT(i.e version vector), instead of the operation on it.
![[Pasted image 20261122222403.png]]
merge(local,incoming) = new CRDT
the merge function should be 
- Commutative => 
  f(a,b)=f(b,a) -> order of operation don't matter
- Associative =>
  same writes combining/merging in different may yield same output f(a,f(b,c))=f(f(a,b),c)
- Idempotent =>
  receive same state multiple time give same output f(a,b)=f(a,f(a,b))=f(f(a,b),b)
from this, order doesn't matter => can put any merges in any order
#### Using GOSSIP protocol
Requires no extra messaging infrastructure
1. Pick starting point![[Pasted image 20261122223014.png]]
2. pick any 2 more ![[Pasted image 20261122223059.png]]
3. in next round this 2 will send to 2 more
   as it doesn't matter if same node receives twice(idempotent) or in any order
   eventually all will become consistent with this new writes.
