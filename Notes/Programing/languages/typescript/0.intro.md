### TypeScript
It is a super set of JavaScript.It add data-types
```js
const name="Meow";
console.log(name);
```
```ts
const name:string="Meow";
console.log(name);
```
It will give type safety.
It add `Static typing` to JS, it does not do anything at runtime(browser knows only runs JS)
## Why TS?
because JS is dynamic and loosely typed => problem because a const can be anything object,primitive,function 
function also don't have return and parameter types which is done is type script
-> it will give error at coding time so, avoided crash during run time
It is made by Microsoft => who use C#

only web-assembly and JS can run on browser
so TS ->compiles to JS
TS is compiler TSC -> is not for optimization it is correctness 
Reason to use TS
- catches a ton of bugs and errors at compile time(fact)
- makes your code more readable and maintainable
- make it easier to refactor and scale your code base(change in one place and gives error in other places where change is needed)
All TS code is not valid JS code.
## TSC compiler
It is a compiler which converts TS code to JS code
## Basic types
```ts
const name:string="meow";
const prot:number=3000;

```
## Type inference
extra overhead of typing types every-time.
TS can infer the types correct
```ts
const name="WERT"
```
it will infer that it is a string -> it can infer types based on context
## Any 
It is a type which is assignable to anything => like normal JS
It is not recommended to use it.
It skips checking => like unsafe
```ts
const something:any="Hello world";
something.some();
```
it will not give error as it is of type any so, it may have a function some in it.
> [!note]
> see difference between any and infer types
## Functions
in function parameters, it is a need to give types
```ts
export function calculateTotal(
	price:number,
	quantity:number,
	discount:number
):number{
	return price*quantity*(1-discount);
}
```
return type can be infer => but for more safety can specify it.
