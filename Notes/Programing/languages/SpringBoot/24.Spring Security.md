### Authentication states
1. Stateful authentication
2. Stateless authentication
HTTPS request are stateless, thus if need to maintain session need to store something.
![[Pasted image 20260831135240.png]]
like now login then try to make user, this HTTP call don't know previous login was done.
![[Pasted image 20260831135543.png]] then for every action need to login again.
this 2 stateless and statefull are arititchure form application to authenticate.
#### StateFull authentication
store session id in browser cookies.
![[Pasted image 20260831140545.png]]
will do mapping of SessionId to authentication object so if that cookies exist they allow to do authorized stuff.
will do cookies information -> ![[Pasted image 20260831140738.png]]
Note : not storing all information in user browser only id whose mapping is done by server to authenticate.
SessionId -> browser
SessionState -> server(full control on server can montior user activities)
Problems
- Storage -> if multiple replica servers are present.![[Pasted image 20260831141358.png]] as login through replica 1 and did request on replica 2, then problem.(hard to maintaine states in distributes system)(LB -> load balancer).Solutions
	- User mapper 1 user always go to same replica(problem load balancer will do uneven distribution which is wrong) 
	- make central DB for authentication objects.![[Pasted image 20260831141742.png]]
- If hacker got sessionId the user comprimized.(rotate cookies time to time)
- session fixation is bad hard to roll.(solve by relogin after 24hr or 1 month)
#### Stateless authentication
with any request send a token for authentication detail is created(not use old authentication).
every request has new authentication no old info/state is stored.
Token -> criendiential given by client to make new authentication.
validate the token -> has user signature, issuer, expery data. -> have special token JWT.
it will use it to create Authentication object using token.
Token types
- Self contained token -> has full information in it to make authentication object.(example JWT)
- opaque token -> not self contained like is like session id need a identifes mapping.![[Pasted image 20260831144506.png]] it is almost stateful. but token service is not part of application.
Bearer `<Token>` -> it is token send by someone who owns the token.
After 1st login the application gives that token to the user which it will use for future actions(that is send the token in header of all request).
optionally can store in cookies still it will be stateless.
stateless => generate new object using the token.
