## DTO
DTO -> data transfer object
it is a POJO class subset of entity -> which will be used.
like in response will send data not meta-data and will be sending a message.
`RequestDTO` and `ResponseDTO`.
make new package DTO ->
```java
public class RequestDto {
    private String name;
    private String email;
    public void setName(String name) {
        this.name=name;
    }
    public String getName() {
        return name;
    }
    public void setEmail(String email) {
        this.email=email;
    }
    public String getEmail() {
        return email;
    }
}

public class ResponseDto {
    private String name;
    private String email;

    public void setName(String name) {

    }
    public String getName() {
        return name;
    }
    public void setEmail(String email) {
        this.email=email;

        return email;

```

now who should convert the request and response DTO to entity. -> whose responsibility -> service(as it has business logic).
but as project grows need to make a mapper package for it.
```java
    public ResponseDto createStudent(RequestDto student) {
        Student mapped=mapToEntity(student);
        Student saved=studentRepository.save(mapped);
        return mapToDto(saved,"Student saved successfully");
    }

    private Student mapToEntity(RequestDto student) {
        Student entity=new Student();
        entity.setName(student.getName());
        entity.setEmail(student.getEmail());

        entity.setDeleted(false);
        entity.setCreatedAt(LocalDateTime.now().toString());
        entity.setUpdatedAt(LocalDateTime.now().toString());
        return entity;
    }
    private ResponseDto mapToDto(Student entity,String message) {
        ResponseDto res=new ResponseDto();
        res.setId(entity.getId());
        res.setName(entity.getName());
        res.setEmail(entity.getEmail());
        res.setMessage(message);
        return res;
    }
```

## Validations
client can send miss-leading data -> like send wrong email.
check if did he send email empty or null.
```java
name ="" or "     " or "a";
email="" or "s@jk@s@ksf" or "hellow@alw.ska,skajs2ks"
```
we can't trust what user send.
can add validation in service layer or make other class for validation which service layer will call.
- but, we should only do business logic on service layer not basic validation(checking if request is correct or not)
- thus, should stop whose invalid data at controller layer only.
- controller -> can add dependency called `spring-boot-starter-validation`.![[Pasted image 20260725112825.png]]
 https://mvnrepository.com/artifact/org.springframework.boot/spring-boot-starter-validation
 ```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
    <version>4.0.6</version>
    <scope>compile</scope>
</dependency>
 ```
 version and scope is optional -> as uses spring boot starter parent so it will take care of version and scope.
 will get many validation based annotation in it.
