Why not hard-code things.
- as need to make thing different based on environment

- security(can't put key and password, etc sensitive data online)
- not make it tightly coupled

```java
@RestController
@RequestMapping("/api")
public class DemoController {

    @Value("${app.welcome.message}")
    private String message;
    @Value("${app.welcome.code}")
    private Integer code;
    @Value("${app.welcome.users}")
    private List<String> users;

    @PostMapping("/greet")
    public ResponseEntity<String> greet(){
        System.out.println(users);
        return ResponseEntity.status(code).body(message+":"+code);
    }
}
```

## Profiling
make equivalent properties file
```properties
spring.application.name=config
server.port=9090
app.welcome.message=Local: welcome to application
app.welcome.code=200
app.welcome.users=Sachin,Rohit,Meow,cat
```
make multiple properties file for different profiles(environment).
```bash
application.properties // main file
application-{profile}.properties
```
make files
```bash
   │   │ * application-dev.properties
   │   │ * application-production.proper
   │   │ * application-staging.propertie
   │   └ * application.properties
```
properties
- `application.properties` -> will have config which are common to all environments.
- `application-{profile}.properties` -> will have environment specific config.
```java
// application-dev.properties
app.welcome.message=dev: welcome to application
// application-production.properties
app.welcome.message=production: welcome to application
// application-staging.properties
app.welcome.message=staging: welcome to application
// application.properties
spring.application.name=config
server.port=9090
app.welcome.code=200
app.welcome.users=Sachin,Rohit,Meow,cat
```
made message profile specific.
how to tell spring boot which config to take ??
- in main `application.properties` -> declare there.
```java
spring.application.name=config
server.port=9090
app.welcome.code=200
app.welcome.users=Sachin,Rohit,Meow,cat

spring.profiles.active=dev
```

## External properties
Problem :-
- if need to say `application.properties` -> which profile to use.
- need to make changes to one file to change environment
as config is in JAR file.
possible solution
- command lines
- environment variables(this comes from OS or defined in CI/CD server etc)
#### Command line
current we use command to run spring boot
```bash
mvn spring-boot:run
```
can select profile 
```bash
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```
by default it will takes only `application.properties`.
make a notification service
```java
@Service
public class NotificationService{
    public String send(){
        return "Here is a notification";
    }
}
```
in controller
```java
@RestController
@RequestMapping("api/notification")
public class NotificationController {
    public NotificationService notificationService;
    public NotificationController(NotificationService notificationService){
        this.notificationService=notificationService;
    }
    @PostMapping
    public ResponseEntity<String> sendNotification(){
        return ResponseEntity.ok(notificationService.send());
    }
}
```
![[Pasted image 20260731172325.png]]
problem is if testing in dev profile -> it will send notification.
so can use `@Profile`.
make notification service a interface.
```java
@Service
public interface NotificationService {
    public String send();
}

@Service
public class NotificationServiceImpl implements NotificationService {
    @Override
    public String send() {
	    // send real notification
        return "Notification sent";
    }
}
```
now will use implementation of notification service as only one implementation.
for dev -> need a dummy implementation for it.
```java
@Service
public class DummyNotificationServiceImpl implements NotificationService {
    @Override
    public String send() {
	    // send dummy notification
        return "Dummy notification sent";
    }
}
```
now 2 implementation how controller decides which to choose.
- can use primary or qualifier
- or give profile
```java
@Service
@Profile("dev")
public class DummyNotificationServiceImpl implements NotificationService {
    @Override
    public String send() {
        return "Dummy notification sent";
    }
}

@Service
@Profile("production")
public class NotificationServiceImpl implements NotificationService {
    @Override
    public String send() {
        return "Notification sent";
    }
}
```
![[Pasted image 20260731174002.png]]![[Pasted image 20260731174028.png]]
now beans are selected for injection based on environment.
if no profile is selected -> will give error as confusion on what to use.
can also pass more profiles
```java
@Service
@Profile({"dev","default","staging"})
public class DummyNotificationServiceImpl implements NotificationService {
    @Override
    public String send() {
        return "Dummy notification sent";
    }
}
```
now can decide bean selection based on profile.
now can profile -> config, bean control it based on profile.
similar can be done for `.yml` file also.
