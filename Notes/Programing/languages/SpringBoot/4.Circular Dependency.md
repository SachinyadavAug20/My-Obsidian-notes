### Solutions
```java
    @Autowired
    private PaymentService ps;

// and 
    @Autowired
    private OrderService os;
```
make constructor dependency injection to field injection.
How field injection happens(like it is private)?
- can inject in private member using reflection API.
Object creation and injection are separated now.
steps
- creates Order service empty object
- create payment service empty object
- inject payment service to order service and vice versa
output
```bash
Payment Done 
get Order 
Order Placed
```
But real flow in for bean A(Order service) and B(Payment Service) for IOC container is
- Create A(partial)
- Create B(get partial A reference)
- A(gets partial B reference)
- B(completes) and A(completes)
Then why circular dependency is problem
- It work but not good practice
- thus, spring boot by default not allow circular dependency
- `spring.main.allow-circular-reference : false`  in spring boot(not in spring core)
There are other methods to resolve circular dependency.
circular dependency make code tightly coupled => why entangled responsibility(SOLID).
if have circular dependency should refactor not make it work.
make changes
```java
@Component
public class OrderService {
    @Autowired
    private PaymentService ps;

    public void placeOrder(){
        ps.pay();
        System.out.println("Order Placed");
        this.getOrder();
    }
    public void getOrder(){
        System.out.println("get Order");
    }
}

@Component
public class PaymentService {
    @Autowired
    private OrderService os;

    public void pay() {
        System.out.println("Payment Done");
        // os.getOrder();
        // not it's responsibility
    }
}

```
it is order service work to get orders.
works and refactor circular to linear dependency.
