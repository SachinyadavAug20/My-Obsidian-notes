#### Problems with 2 phase locking
- All transactions need to grab lock(SLOW!!), when rarely actually need to.
  why grab a lock when you could just run as normal and correct mistakes after they happens ?
solve this using Serializable Snapshot isolation.
## Serializable Snapshot isolation
will read from snapshots(consistent state of DB at after transaction T) 
look for read -> modify -> update cycle when see problem take actions
