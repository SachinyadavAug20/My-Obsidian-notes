having dependencies is not a problem.
```java
public class OrderService {
    NotificationService ns;
    OrderService(NotificationService ns){
        this.ns=ns;
    }
    public void placeOrder(){
        System.out.println("Order has been placed.");
        ns.SendNotification();
    }
}
```
in place from where called order service change that to make notification service.
```java
package sachin.yadav;

import sachin.yadav.notification.EmailService;
import sachin.yadav.notification.NotificationService;

public class App {
    public static void main( String[] args ) {
        NotificationService notificationService=new EmailService();
        OrderService orderService=new OrderService(notificationService);
        orderService.placeOrder();
    }
}
```
now better SOLID principle.
This is called dependency injection => take away dependency/responsibility from where it don't belong. and will inject that dependency in it from somewhere else.

and use as
```java
package sachin.yadav;

import sachin.yadav.notification.EmailService;
import sachin.yadav.notification.NotificationService;

public class App {
    public static void main( String[] args ) {
        NotificationService notificationService=new EmailService();
        OrderService orderService=new OrderService();
        orderService.SendNotification(notificationService);
        orderService.placeOrder();
    }
}
```

## IOC(Inversion of control)
It is similar to dependency injection(not same).
Control ->initial design ![[Pasted image 20260705151151.png]]
after dependency injection main has more control
![[Pasted image 20260705151250.png]]
see control of email service is inverted. this is called as IOC(inversion of control).
now, order service has no control on which notification it sends.(control of notification service inverted from begin inside order service to outside(in main)).
#### IOC and DI relationship
IOC is idea or principle.
DI is approach/technique to achieve IOC
- main controls/configures everything.
- spring framework eases this config and handle control automatically. -> it has IOC controller which does all this control
- IOC container will
	- create objects.
	- manage objects.
	- connect objects together.
it spring we don't use `new` keyword as most of it managed by IOC controller.
Object --> java code
Beans --> Spring IOC container 
Beans are object manager by spring IOC container.(all beans are object but all object are bot beans).
