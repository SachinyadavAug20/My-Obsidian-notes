## Replication
mean many copies of DB.
### Life with Replication
![[Pasted image 20261115211007.png]]
different part of world uses different DB.
Pros
- Redundant data -> no lost of data(backups)
- Increased DB throughput(less load on single DB less)
- Can Geo-locate user to closed DB and connect them so they experience fast speed.
 How to replicate => 2 types 
## Synchronous replication
![[Pasted image 20261115213359.png]]
all replica say write is done then, only confirm(consider valid) else retry.
it gives strong consistency
writes takes longer
## Asynchronous Replication
![[Pasted image 20261115213816.png]]
will perform the write => get say from that particular replica and later in free time that replica will communicate with other to do same write.
in background replica will asynchronously replicate the write.
This is eventual consistency.
faster write

> [!NOTE]
> In modern web-apps we use Asynchronous Replication, if stale reads is un-acceptable then use synchronous Replication

## How to replicate
there are 3 ways 
![[Pasted image 20261115214337.png]]
1. SQL
   do the same query in all replicas
   Problem:
   sometime non-deterministic like `time.now` will give different output so, inconsistent data between replicas.
   un-acceptable
2. Use Write ahead log
   what exact byte value written where is logged
   thus, exact replicas achieved
   problem
   if replicas run different software(`MySQL` and `PostgreSQL`) then, different software uses different memory address
   un-acceptable
3. Replication log
   It is logic log => what to do as SQL(with all non-deterministic part take out)
   ![[Pasted image 20261115214853.png]]
   it is used in practice
   it comes at a cost of creating this logs(extra overhead)
