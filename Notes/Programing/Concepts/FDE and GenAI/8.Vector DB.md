## ANN algorithm
there are 2 algorithm ->
1. `IVF` : Inverted file index
2. `HNSW` : Hierarchical navigable small worlds
### IVF Algorithm
break down all space into cluster => all moves together.
![[Pasted image 20261015152443.png]]
100 million => cluster of 1000.
![[Pasted image 20261015152402.png]]
it will find closed cluster to the query and compare with all vector in that cluster ![[Pasted image 20261015152553.png]]
How to find closest cluster => using centroid approach.
make a vector at the centroid of the cluster that is the average using K-mean algorithm.
![[Pasted image 20261015160435.png]]
compare the query vector with the centroid to choose a cluster.
![[Pasted image 20261015160655.png]] 
clustering is pre-computed.
Problem:
- when query at the boundary of a cluster then, will have problems as nearest might be in other cluster.
  ![[Pasted image 20261015161837.png]]
- This leads to approximation. => need to take a trade off
  compare with top k cluster thus, accuracy increases(Recall).
### HNSW (Hierarchical Navigable Small Worlds)
it solves the problem of IVF.
consider all vectors as nodes of a graph => connected by edges all are connected.
![[Pasted image 20261015162644.png]]
find distance of Q from each node ![[Pasted image 20261015164151.png]]
not to connect all with all because it will lead to brute force.
will have express-way => ![[Pasted image 20261015172554.png]]
express way has direct connectivity => local road have high precision, highway have low precision.
try to impose logic to make the HNSW.
express-way is very spares(less density) and skips small stops.
![[Pasted image 20261015173004.png]]
make layers below it which will be more dense.
![[Pasted image 20261015173149.png]]
at very bottom all nodes very dense
![[Pasted image 20261015173240.png]]
for a query vector which lies close to X.
this not shows linear connectivity but,![[Pasted image 20261015174048.png]]
start from highway and when we are close make use of lower level and make it precise.
![[Pasted image 20261015175332.png]]
now word meaning HNSW (Hierarchical Navigable Small Worlds)
- Hierarchical -> make levels.
- Navigable -> navigate between levels.
- Small Worlds -> at bottom smallest world.

#### 256 centroid trick
full space divided into 256 centroid.
as 256 unique centroid => need 256 unique possibility => 8 bits.
![[Pasted image 20261016171133.png]]
that is 1 bytes.
thus 1 centroid = 1 byte.
now => 32 byte vector compressed to 4 bytes. --> `8x` compression.
for 1536 dimension,
![[Pasted image 20261016171330.png]]
break dimension into chuck of 96 dimension => 1536/96 = 16.
each 16 dimension chuck represented by 1 dimension out of 256.
16 dimension -> 1 bytes.
96 chunk -> 96 bytes.
![[Pasted image 20261016172838.png]]
only have 256 unique(representative) centroid which is represented by 1 byte.
it is lossy compression => data is loosed.
need to take trade off for it.
