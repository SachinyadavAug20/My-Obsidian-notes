## Histroy of programming
why need of OPPs, what was wrong is structural programming ?
- Machine language (1/0) -> direct interact with CPU.  => prone to error, tedious, no scalable
- Assembly level language -> use english keywords, converted to machine code by assembler. => tightly-coupled with hardware, prone to error, no scalable, a bit tedious.
- Procedural programming -> before OPPs. has function,loops,blocks,conditionals etc. like recipe set of instruction -> e.g C => complex problem can't be solved
- OOP -> 
	- real world modelling 
		- to solve real word problem need to model the real world. objects interacts.
		- object has -> characteristics(variable or indentifiers) and behavior(methods)
		- example
			- Car  
				- characteristics engine,brand,model,wheels,isEngineOn ...
				- can/behaviour start(),stop(),gearShift(),accelrate()...
			- Ownwer of car
				- characteristic rcNo,car,name...
				- behaviour -> Drive(Car c) ![[Pasted image 20260906213110.png]] as allow owner to have multiple cars(can make any number of object from 1 blue print).
	- Data security.
	- Scalable/reuseable.
Real life object -> need to also map it's action,relations,traits.
thus have 4 pillars of OOPs.
- Abstraction
- Encapsulation
- Inheritance
- Polymorphism
