# Basics of C++

## 1. Header Files & Basic Setup

- `#include <bits/stdc++.h>`: A special header file that includes **all standard headers required for Competitive Programming (CP)**. Using this eliminates the need to include individual libraries like `<iostream>`, `<vector>`, or `<algorithm>` one by one.
    

## 2. Core Data Types & Truth Values

- **Standard Types:** `char`, `int`, `float`, `double`, `bool`.
    
- **Boolean Reality:** _"All non-zero numbers are considered as true."_ Only `0` is treated as `false`.
    
- **Integer Hierarchy (Size Constraints):** Because an ordinary integer has fixed memory constraints, sizes scale up as follows:
    
    $$\text{int} < \text{long int} < \text{long long int}$$
    

## 3. Pre-Increment vs. Post-Increment

|**Syntax**|**Mechanics**|**Operational Order**|
|---|---|---|
|`++a`|**Pre-increment**|Increments value $1^{\text{st}}$, then uses it in the expression|
|`a++`|**Post-increment**|Uses the current value first, then increments it later|

## 4. Typecasting

- `(int) C`: Explicitly converts a variable `C` to an integer format.
    
- **Example:** If `char c = 'a';`, then performing `(int)c` yields its ASCII value: **`97`**.
    

## 5. Standard Input Mechanics (`cin`)

- **Behavior:** `cin >> a >> b >> c;` takes inputs continuously until it encounters a **space** or a newline character (`'\n'`), which it skips.
    
- **Input Flexibility:** Both format layouts below are equally valid for processing input tokens:
    

**Layout A (Newline separated):**

```
1
2
3
```

**Layout B (Space separated):**

```
1 2 3
```

## 6. Operator Precedence & Type Promotion

When executing expressions, the output calculation is automatically promoted to the **higher data type** involved in the equation.==> type promotion

### Output Type Promotion Hierarchy (Increasing Priority):

```
▲ Double      (Highest Priority)
│ Float
│ Long Long Int
│ Long Int
│ Int
│ Character   (Lowest Priority)
```

### Evaluation Rules (Similar to BODMAS):

- **Highest Priority Operations:** `()`, `[]`, `->`, `.`, `++`, `--`
    
- **Next Tier Operations:** `*`, `/`, `%`
    
- **Associativity:** Evaluates from **Left to Right**.
    

## 7. Data Ranges & Overflow Mechanics

### Common Type Limits

- **`int`:** $\approx (-10^9 \text{ to } 10^9)$
    
- **`long int`:** $\approx (-10^{12} \text{ to } 10^{12})$
    
- **`long long int`:** $\approx (-10^{18} \text{ to } 10^{18})$
    
- **`float` / `double`:** Capable of storing **very big** numerical limits.
    
- **`INT_MAX`:** A pre-defined global macro variable that stores the maximum capacity limit of a signed integer ($\approx 2.1 \times 10^9$).

### Cyclic Overflow Behavior

Exceeding upper bounds or lower bounds causes the values to cleanly loop back around in a circle:

```cpp

    MAX[+ve Max / INT_MAX] -->|Overflow +1| MIN[-ve Min / INT_MIN]
    MIN -->|Underflow -1| MAX

    style MIN fill:#bbf,stroke:#333,stroke-width:2px
```

### Forcing Higher Precision Calculations (`1LL`)

- **`1LL`** explicitly represents the literal value `1` stored as a **`long long integer`**.
    
- **CP Trap Fix:** If you multiply two huge standard integers `a * b`, the calculation might overflow _before_ being assigned to a long long variable.
    
- **Solution:** Write the expression as `a * 1LL * b`. This forces the intermediate calculations to occur cleanly in **`long long int`** precision space.
    

## 8. Floating-Point Issues (`double` / `float`)

> [!warning] Precision Error Warning
> 
> Avoid relying heavily on `double` and `float` data types during precise mathematical checks in Competitive Programming due to persistent **precision errors**.

- **Scientific Notation Output:** Large decimal formats naturally print out in compressed scientific syntax (e.g., `1e+10`).
    
    - _Fix:_ Wrap output handling with `<< fixed <<` to force absolute decimal expansion.
        
- **Excessive Trailing Zeros:** Raw fixed formatting can print out visually bloated rows of zeros (e.g., `10000000000.000000`).
    
    - _Fix:_ Pair your stream output using `<< setprecision(...)` to bind exactly how many points display.
        
- **Inaccuracy at Extreme Scales:** Floating-point numbers lose exact digital tracking at huge sizes. For instance, evaluating an expression value like `1e24` can misrepresent numbers internally as messy fractional estimates like `9999...`. Avoid them whenever structural precision is absolute!
