## Race condition
It is means write is confirmed in the DB => like completed fully.
Examples of race condition
#### Dirty write
![[Pasted image 20261107220607.png]]
it is mixed some person's order and other's address.
Dirty: writing over uncommitted writes.
this leads to inconsistent states and breaks some in-variances.
##### Fix
![[Pasted image 20261107223312.png]]
lock a row only 1 person only can work on 1 row and give lock after committing only.
![[Pasted image 20261107223514.png]]
Problem if he locked other row and you are waiting for 2nd lock and Donald is waiting for 1st to open => dead lock.
solve => order of row access is defined no breaking order or DB have dead lock detection and open it.
#### Dirty reads
![[Pasted image 20261107223656.png]]
reads uncommitted changes is dirty read.
##### Fix
same row level lock can be applied.
but, read is non-destructive and lock is expensive so, store the old value till it is committed.
![[Pasted image 20261107224146.png]]

Any database which need to protect against this dirty read and dirty writes need Read committed isolation.
