will talk to both nodes(each node will grab look and give acknowledgement for request).

if can't commit => ![[Pasted image 20261127222938.png]]
if can do it both say OK => in local commit log of the coordinator(as if coordinator goes down thus, maintain log as node have lock and are waiting).
and will do commit to both nodes => will send success(always success as they have did the check and send OK that they can do the commit) to coordinator.

## Problems with 2-phase commit
Too many points of failure(as many steps)
- Coordinator goes down ? no transactions can proceed, receiving nodes hold locks and can't touch rows.
- Receiver goes down ? transaction can't commit, coordinator needs to send it messages forever until it comes back up.
very little fault tolerance after both node said OK -> will do forever check.
## Conclusion
Distributed transactions(necessary for cross-partition writes and global secondary index) are hard! we need to make it more fault tolerant, but they're still slow(as many steps)!
thus, try to avoid cross-partition writes and global secondary index should be avoid.
improve partition strategy more.
