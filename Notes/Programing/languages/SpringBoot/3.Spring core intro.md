It is similar to dependency injection(not same).

#### IOC and DI relationship
IOC is idea or principle.
DI is approach/technique to achieve IOC
- main controls/configures everything.
- spring framework eases this config and handle control automatically. -> it has IOC controller which does all this control
- IOC container will
	- create objects.
	- manage objects.
	- connect objects together.
it spring we don't use `new` keyword as most of it managed by IOC controller.
Object --> java code
Beans --> Spring IOC container 
Beans are object manager by spring IOC container.(all beans are object but all object are bot beans).
## IOC container
It handle all object => it make all object and handles them, wire dependencies.
need a basic dependency => [Maven Repository: org.springframework » spring-context](https://mvnrepository.com/artifact/org.springframework/spring-context)
Object managed by IOC container are called beans.
There are 2 ways
- Annotations based
- XML configuration based

Why constructor injection is recommended?
- Dependency get wired at the time of object creation.
- final can be used
- easy to test the class(unit test)
Steps for `ApplicationContext`(IOC container):
1. Spring start the application
2. Spring reads `AppConfig.java`
3. Spring process `@ComponentScan(Package)`
4. Spring finds `@Component` classes
5. Spring creates bean definitions ![[Pasted image 20260706145305.png]]=> there is a interface name `Bean defination` in spring
6. Spring start creating objects
