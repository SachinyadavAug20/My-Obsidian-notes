## Quorums
It is a way to have instant reads of writes without read repair or anti-entropy
![[Pasted image 20261124183954.png]]
steps => for N node(N=5).
writer will perform writes to W node(W=3) => waits for confirmation from W nodes to say the writes are successful.
to make sure read is done it reads from R nodes(R=3).
this, will make sure there is at-least 1 node will have updated value.
W+R > N ---> Will have Quorum reads and write due to math.
## Is it strong consistency
no because not all will return updated value but, at-least one will and that will update rest using read repair.
some cases where it fails
#### Case 1) Race condition
W=2 and R=2
![[Pasted image 20261124184846.png]]
due to race condition nodes disagree on which writes are latest.
same time read give different answer
![[Pasted image 20261124185043.png]]
#### Another case) Failed writes
N=3 W=2 R=2
out of 2 writes 1 pass and one fails(write is failed and should be reverted/rollback(not possible)).
![[Pasted image 20261124185310.png]]
#### Sloppy Quorums
one cluster in a region(America and Asia) goes down.
will redirect writes from that region to other region cluster.
![[Pasted image 20261124185516.png]]
N=3 W=2 R=2 ---> quorums writes.
but, if cluster 1 comes back and N increased;
![[Pasted image 20261124185618.png]]
N=6 R=2 W=2 ---> not quorum writes.
Solved using transfer data from cluster-2 to cluster-1.
It is called hinted hand-off.
## Conclusion
Quorums are great, but they are't perfect!
Leaderless database setups can be good for certain application, but if you need completely correct data, don't rely on them!
