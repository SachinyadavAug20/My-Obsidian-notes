Why not hard-code things.
- as need to make thing different based on environment
- so code should be same and logic will be constant
- security(can't put key and password, etc sensitive data online)
- not make it tightly coupled
thus make a config file -> till now `application.properties` and `YAML` are internal config not external config(as they are part of JAR file produced).
![[Pasted image 20260730192545.png]]
- properties -> uses `.` operator and flat key value pair.(problem need to write same thing(`like app.welcome.message app.welcome.code app.welcome.text`) many time no structure)
- YAML -> use hierarchical form
```yml
# spring.application.name=config
# app.welcome.message=Local: welcome to application
# server.port=9090


spring:
  application:
    name: config
server:
  port: 9090
app:
  welcome:
    message: Local welcome to application
    code: 200
    users: Sachin,Rohit,Meow,cat
```
if both file `.properties` and `.yml` 
so delete the properties file, now use it
```java
@RestController
@RequestMapping("/api")
public class DemoController {

    @Value("${app.welcome.message}")
    private String message;
    @Value("${app.welcome.code}")
    private Integer code;
    @Value("${app.welcome.users}")
    private List<String> users;

    @PostMapping("/greet")
    public ResponseEntity<String> greet(){
        System.out.println(users);
        return ResponseEntity.status(code).body(message+":"+code);
    }
}
```
as internally spring flat this tree thus, it prefers the `.properties` file over `.yml`.

## Profiling
make equivalent properties file
```properties
spring.application.name=config
server.port=9090
app.welcome.message=Local: welcome to application
app.welcome.code=200
app.welcome.users=Sachin,Rohit,Meow,cat
```
make multiple properties file for different profiles(environment).
```bash
application.properties // main file
application-{profile}.properties
```
make files
```bash
   │   │ * application-dev.properties
   │   │ * application-production.proper
   │   │ * application-staging.propertie
   │   └ * application.properties
```
properties
- `application.properties` -> will have config which are common to all environments.
- `application-{profile}.properties` -> will have environment specific config.
```java
// application-dev.properties
app.welcome.message=dev: welcome to application
// application-production.properties
app.welcome.message=production: welcome to application
// application-staging.properties
app.welcome.message=staging: welcome to application
// application.properties
spring.application.name=config
server.port=9090
app.welcome.code=200
app.welcome.users=Sachin,Rohit,Meow,cat
```
made message profile specific.
how to tell spring boot which config to take ??
- in main `application.properties` -> declare there.
```java
spring.application.name=config
server.port=9090
app.welcome.code=200
app.welcome.users=Sachin,Rohit,Meow,cat

spring.profiles.active=dev
```
