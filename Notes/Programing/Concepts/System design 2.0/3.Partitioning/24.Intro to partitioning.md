## Partitioning 
Divide data(key value) into parts.
There are different ways to do partitioning.
### Range based partitioning
each partition has data from a set range.
![[Pasted image 20261126204712.png]]
here, sorted by first letter in name.
Pros
- Similar keys on same node, good locality for range queries.(as partition need might be on different computer thus networks slow.)
Cons
- Hot-spots => as X-Z section contains no entries and some partition have most of the data(called hot-spots) => thus need to partition this partition
need to shard/partitions in a better way
### Hash range based partitioning
range based on hash value of the data.
As based on hash value => guarantees evenly distribution of data among partitions.
![[Pasted image 20261126205216.png]]
our hash give 1-1000 number for a string.
Pros
- Relatively even distributions of keys, less hotspots(provided a good hash function)
Cons
- No data locality for range queries
need to get locality using secondary index
### Secondary indexes
It is a additional index to primary index => it is 2nd copy of data based on that index.
there are 2 ways to do secondary index in partitions
#### Local secondary indexes
![[Pasted image 20261126205822.png]]
if data of player hash based range shard-ed/partition.
need to shard by height => will store same copy on this same partition desired ordered.
![[Pasted image 20261126210124.png]]
can do query based on height and range queries as indexed.
but, still need to search in many nodes.(both indexed nodes).
Pros
- No need o perform any extra writes over the network
Cons
- To find all players with a given height, we need to read from every single partition.(because it is local)
solved by global secondary index
### Global secondary index
take index of all partition and shard them for this index
![[Pasted image 20261126210611.png]]
each shard/partition has it's range of heights and hash based keys.
![[Pasted image 20261126210744.png]] => it is addition to hash based list
Pros
- Now reads using the index require reading from only one node.
Cons
- We may have to write to multiple shards at once requires(based on hash and based on height range)
  thus, slower writes may need to writes to different place
  also need to make sure both writes happens for consistency
need to have distributed transaction to solve this cons.
