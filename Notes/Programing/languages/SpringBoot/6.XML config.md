previously used annotation based config. => `@Component`,`@Bean`,`@ComponentScan`
XML based is mostly used in legacy code.
Both are ways to configure of IOC container
## XML config
It is complex compare to annotation base.
IOC container -> need configuration metadata.
```bash
    src
   │  main
   │ │  java
   │ │ └  sachin
   │ │   └  yadav
   │ │     │  App.java                W
   │ │     └  OrderService.java
   │ └  resources
   │   └ 󰗀 Bean.xml           // config file
   └  test
```
in app
```java
public class App {
    public static void main( String[] args ) {
        ApplicationContext context=new ClassPathXmlApplicationContext("bean.xml");// this file in class path
    }
}
```
in XML file => copy from internet [XML config](https://docs.spring.io/spring-framework/docs/4.2.x/spring-framework-reference/html/xsd-configuration.html)
```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="
        http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd">
    <bean id="orderService" class="sachin.yadav.OrderService"/>
</beans>
```
rest all life cycle of bean remains the same.
can use it
```java
import org.springframework.context.ApplicationContext;
import org.springframework.context.support.ClassPathXmlApplicationContext;

public class App {
    public static void main( String[] args ) {
        ApplicationContext context=new ClassPathXmlApplicationContext("Bean.xml");
        // get bean by type
        OrderService orderService=context.getBean(OrderService.class);
        orderService.placeOrder();
        // get bean by name/id
        OrderService orderService1=(OrderService)context.getBean("orderService");
        orderService1.placeOrder();
    }
}
```
can also do multiple definition of same object.
```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="
        http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd">
    <bean id="orderService" class="sachin.yadav.OrderService"/>
    <bean id="orderService1" class="sachin.yadav.OrderService"/>
</beans>
```
now by type will be error as need primary but id is unique thus, bean by id is better.
there is 3rd way
```java
public class App {
    public static void main( String[] args ) {
        ApplicationContext context=new ClassPathXmlApplicationContext("Bean.xml");
        OrderService orderService=context.getBean("orderService",OrderService.class);
        orderService.placeOrder();
    }
}
```
if not given id then, it won't auto-create an id.it will have no did thus, won't be able to get bean by id.
```xml
    <bean class="sachin.yadav.OrderService"/>
```
can have many bean(also have name)
```xml
<bean id="orderService" name="orderServiceBean, os" class="sachin.yadav.OrderService"/>
<bean id="paymentService" name="paymentServiceBean, ps" class="sachin.yadav.PaymentService">
```
can also fetch by name(alias) for same thing.
#### Injection in XML
example injection
```java
public class OrderService {
    private PaymentService paymentService;
    OrderService(PaymentService paymentService){
        this.paymentService=paymentService;
        System.out.println("Created bean");
    }
    public void placeOrder(){
        System.out.println("Order Placed");
        paymentService.pay();
    }
}
```
xml
```xml
  <bean id="paymentService" class="sachin.yadav.PaymentService"/>
  <bean name="orderService,os" id="orderService" class="sachin.yadav.OrderService">
    <constructor-arg ref="paymentService"/>
  </bean>
```
if complex constructor.
```java
package sachin.yadav;

public class PaymentService {
    private String type;
    private int retryCount;
    public PaymentService(String type,int retryCount){
        this.type=type;
        this.retryCount=retryCount;
    }
    public void pay(){
        System.out.println("Payment Done using "+type+", after "+retryCount+" tries.");
    }
}
```
in config can wire it
```xml
  <bean id="paymentService" class="sachin.yadav.PaymentService">
    <constructor-arg value="UPI"/>
    <constructor-arg value="3"/>
  </bean>
  <bean name="orderService,os" id="orderService" class="sachin.yadav.OrderService">
    <constructor-arg ref="paymentService"/>
  </bean>
```
can index it
```xml
  <bean id="paymentService" class="sachin.yadav.PaymentService">
    <constructor-arg index="1" value="3"/>
    <constructor-arg index="0" value="UPI"/>
  </bean>
  <bean name="orderService,os" id="orderService" class="sachin.yadav.OrderService">
    <constructor-arg ref="paymentService"/>
  </bean>
```
now order not matter as given index.
also can pass name/ instead of index.
```xml
  <bean id="paymentService" class="sachin.yadav.PaymentService">
    <constructor-arg name="retryCount" value="3"/>
    <constructor-arg name="type" value="UPI"/>
  </bean>
  <bean name="orderService,os" id="orderService" class="sachin.yadav.OrderService">
    <constructor-arg ref="paymentService"/>
  </bean>
```
for setter injection
```java
public class OrderService {
    private PaymentService paymentService;
    public void setPaymentService(PaymentService paymentService){
        this.paymentService=paymentService;
    }
    public void placeOrder(){
        System.out.println("Order Placed");
        paymentService.pay();
    }
}
```
config using
```xml
  <bean name="orderService,os" id="orderService" class="sachin.yadav.OrderService">
    <property name="paymentService" ref="paymentService"/>
  </bean>
```
name -> which property set --> it assumes setter name will be `setPaymentService`.
if setter name is `setPaymentServiceBean` then name = `PayementServiceBean`.

#### Types of initialization.


#### Post construct and pre destroy
can make methods and pass there name in XML.
```java
public class UserService {
    public UserService(){
        System.out.println("Created UserService");
    }
    public void initPostConstruct(){
        System.out.println("After contruct");
    }
    public void destroyPreDestroy(){
        System.out.println("Before destroy");
    }
}

// main
public class App {
    public static void main( String[] args ) {
        ClassPathXmlApplicationContext context=new ClassPathXmlApplicationContext("Bean.xml");
        UserService userService=(UserService)context.getBean("userService");
        context.close();
    }
}
```
use in XML
```xml
  <bean 
    id="userService" 
    class="sachin.yadav.UserService"
    init-method="initPostConstruct"
    destroy-method="destroyPreDestroy"
   />
```
if it was prototype then, clean up will not be called.
#### Conclusion
Why not use XML today??
- file becomes large all in one file.
- to check need to visit single file.(can do many files and inheritance using(`<import resource="beans.xml">`))
- error prone and complex.
IOC -> don't care about weather using annotation of XML based config.
