It is a abstraction over JDBC.
```java
@RestController
@RequestMapping("/api/students")
public class StudentController {
    private StudentService studentService;

    StudentController(StudentService studentService) {
        this.studentService = studentService;
    }

    @PostMapping
    public ResponseEntity<Student> saveUser(@RequestBody Student student) {
        return ResponseEntity.ok(studentService.SaveUser(student));
    }

    @GetMapping
    public ResponseEntity<List<Student>> getAllUser() {
        return ResponseEntity.ok(studentService.getAllUser());
    }

    @GetMapping("/{id}")
    public ResponseEntity<Student> getUserById(@RequestBody Long id) {
        return ResponseEntity.ok(studentService.getUserById(id));
    }

    @PutMapping("/{id}")
    public ResponseEntity<Student> updateUser(@RequestBody Student student, @RequestBody Long id) {
        return ResponseEntity.ok(studentService.updateUser(student, id));
    }
}
```
make all operation doable via API.
Raw JDBC has boiler plate.
- Open a connection.
- Create a statement.
- Close connection/Statement.
- Catching SQL Exception
Spring handle all of this, so handle what changes
- SQL Query
- Result mapping
- Parameter value
It make Spring JDBC(It is enhancement over raw JDBC).

Has a interface which will bring connection.
connection -> very expensive resource(limited througput of connection).
Thus, can't make new connection everytime. -> solved by connection pool.(will have active connection).

close -> put connection put back in pool.
