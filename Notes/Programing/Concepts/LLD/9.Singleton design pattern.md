## Singleton class
it is a class whose only one instance can be created.
Implementing such class is singleton design pattern.
when try to make more instance of this class it give that single object.
need to make a class whose only 1 instance can be created.

in new A(); -> internally it makes object in the heap memory.
![[Pasted image 20260925180850.png]]
we call constructor when making a new object.
if not given constructor gives default constructor.
problem is due to `new` keyword.
```cpp
#include<iostream>

using namespace std;

class NoSingleton {
public:
    NoSingleton() {
        cout << "Singleton Constructor called. New Object created." << endl;
    }
};

int main() {
    NoSingleton* s1 = new NoSingleton();
    NoSingleton* s2 = new NoSingleton();

    cout << (s1 == s2) << endl;
}
```
O/P : ![[Pasted image 20260925184605.png]] -> False(as this are different objects)
restrict user to make more object -> constructor can be called as it is public.
if private constructor -> can't make object using `new`.
we need to allow only 1 and return already existing one.
give public method to allow get object. -> static method for that class.
```cpp
#include<iostream>

using namespace std;

class Singleton {
private:
    static Singleton* instance;

    Singleton() {
        cout << "Singleton Constructor called" << endl;
    }

public:
    static Singleton* getInstance() {
        if(instance == nullptr) {
            instance = new Singleton();
        }
        return instance;
    }
};

// Initialize static member
Singleton* Singleton::instance = nullptr; // in cpp initial here, in java can do in class also

int main() {
    Singleton* s1 = Singleton::getInstance();
    Singleton* s2 = Singleton::getInstance();

    cout << (s1 == s2) << endl;
}
```
O/P : true -> as same object.
can improve it
#### Thread safety
problem
- if 2 thread execute the get instance method at the same time will let to problems
- both thread will end up creating new object.
solved by using lock using `mutex`.
```cpp
#include<iostream>
#include <mutex>

using namespace std;

class Singleton {
private:
    static Singleton* instance;
    static mutex mtx;

    Singleton() { 
        cout << "Singleton Constructor Called!" << endl; 
    }
 
public:
    static Singleton* getInstance() {
        lock_guard<mutex> lock(mtx); // Lock for thread safety
        if (instance == nullptr) {
            instance = new Singleton();
        }
         return instance;
    }
};
 
// Initialize static members
Singleton* Singleton::instance = nullptr;
mutex Singleton::mtx;

int main() {
    Singleton* s1 = Singleton::getInstance();
    Singleton* s2 = Singleton::getInstance();

    cout << (s1 == s2) << endl;
}
```
locking is expensive operation -> need to avoid locks as much as possible.
if need to create new instance then, only need to net lock.
```cpp
#include<iostream>
#include <mutex>

using namespace std;

class Singleton {
private:
    static Singleton* instance;
    static mutex mtx;

    Singleton() { 
        cout << "Singleton Constructor Called!" << endl; 
    }
 
public:
    // Double check locking..
    static Singleton* getInstance() {
        if (instance == nullptr) {  // First check (no locking)
            lock_guard<mutex> lock(mtx);  // Lock only if needed
            // check 2nd time as if two thread entered if at same time and race for lock then, one will get lock and other will not so for that other need to check if already assigned don't assigne again -> multiple thread can enter outer if but, can't enter inner if
            if (instance == nullptr) {  // Second check (after acquiring lock)
                instance = new Singleton();
            }
        }
        return instance;
    }
};
 
// Initialize static members
Singleton* Singleton::instance = nullptr;
mutex Singleton::mtx;

int main() {
    Singleton* s1 = Singleton::getInstance();
    Singleton* s2 = Singleton::getInstance();

    cout << (s1 == s2) << endl;
}
```
simpler way is -> eager initialize the instance and use that only.
```cpp
#include<iostream>
#include <mutex>

using namespace std;

class Singleton {
private:
    static Singleton* instance;

    Singleton() { 
        cout << "Singleton Constructor Called!" << endl; 
    }
 
public:
    static Singleton* getInstance() {
        return instance;
    }
};
 
// Initialize static members
Singleton* Singleton::instance = new Singleton();

int main() {
    Singleton* s1 = Singleton::getInstance();
    Singleton* s2 = Singleton::getInstance();

    cout << (s1 == s2) << endl;
}
```
pros
- no if else
- no locks
cons
- if class is expensive creating is memory and resource -> will waste memory if not need
- eager method is not practical => as make it slow
#### Conclusion
- create a private constructor.
- create a static instance(`getInstance`) that returns the same instance everytime.
#### Real word use
1. Logging system -> logger will make 1 instance entire application will make use of one object to make log.
2. Database connection -> as it is expensive object so make only 1 instance.
3. configuration manager -> config files for all services => API key stored in a config so, single config file will act as single source of truth for the whole app.
opposite side is user object, client object, player, account etc.
thread safety need for singleton.
