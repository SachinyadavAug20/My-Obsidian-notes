## Cross-Cutting
Make a based spring web project
![[Pasted image 20260804170600.png]]
```java
@Component
public class StudentService {
    public Student createStudent(Student student){
        // business logic
        return student;
    }
}

@RestController
@RequestMapping("/api/students")
public class StudentController{
    public StudentService studentService;
    StudentController(StudentService studentService){
        this.studentService = studentService;
    }
    @PostMapping
    public ResponseEntity<Student> createStudent(@RequestBody Student student){
        return ResponseEntity.ok(studentService.createStudent(student));
    }
}
```
Similar can have order, payment etc service.
need to write infra logic or helper -> to log what is happening.
so can log the timer -> 
```java
@Component
public class StudentService {
    public Student createStudent(Student student){
        long start = System.currentTimeMillis();
        // business logic
        long duration = System.currentTimeMillis() - start;
        System.out.println("Duration is "+duration+" ms");
        return student;
    }
}
```
But it is not service responsibility to do this timing, permission(if call by other service which has not checked in filter), cache and logging.
Types of logic
- Business logic
- Infra logic/Supporting logic(boiler plate)
#### Concerns
area of interest of a application. example
![[Pasted image 20260804180241.png]]
- Student Management -> `StudentService`
- Payment Management -> `PaymentService`
- Order Management -> `OrderService`
 Thus, called business logic concerns are vertical -> in one class all methods for it are in same code/class.
 On contrary
 ![[Pasted image 20260804180638.png]]
 It is not vertical as need it in many class/code => that is horizontal concerns.
 Thus, infra concern are called as cross-cutting concerns.
 ##### Problems with cross-cutting concerns are 
 - Scattering -> this class `loggingService` is used in many class thus scattered everywhere.
 - Tangling -> many class `loggingService`,`SecurityService`,`TimingService` etc are tangled in one class/controller.
 ![[Pasted image 20260804181559.png]] without infra logic ![[Pasted image 20260804181621.png]]
  But need to do infra logic for production So,Possible solution
 1. But infra logic class(like utility class with static method), but will need to call them in it.(not work)
 2. Inheritance -> make super class called `LoggingService` and who ever wants to log extend it and get it's method and use it. But still need to have extra code for calling parent class method.(not work)
 3. Wrapper class -> It comes from decorator design pattern.
	- Controller delicate it's task to service
	- so, wrap the service -> to do all logging 
	- ![[Pasted image 20260804183742.png]]
	- Decorator is special object which behaves like the service(Business object) because, that is decorator inherits controller.![[Pasted image 20260804184259.png]]
	- ![[Pasted image 20260804184430.png]]
	- Decorator will have to override student service method -> `createStudent()` -> it will perform infra logic and then call `createStudent()` of actual implementation of service.
	- ![[Pasted image 20260804184918.png]]
	- This solves the actual problem
