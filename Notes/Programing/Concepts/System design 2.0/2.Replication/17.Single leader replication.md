### Benefits of Single leader replication
1. Many copies of data => increased durability
2. Increased read throughput(bandwidth for read increased)
### Failure scenarios
#### Follower goes down
![[Pasted image 20261117200747.png]]
Before going down follow => seen all writes till 50(in replication log which send by lead to follower).
leader due to logs will send from 51 to latest to revived follower.
#### When leader goes down
big problem => 3 case hard to offer solution for this
##### Case 1
if only network is done leader is up 
![[Pasted image 20261117210821.png]]
network problem >> if will have replace leader hard to know if leader is down as it is asynchronous thus, don't know when leader will talk to follower.
##### Case 2
if leader is down on replication log 80.
![[Pasted image 20261117211205.png]]
follow don't get all 80 logs.
thus, lost logs(as new leader/caption will have till 70 only).
![[Pasted image 20261117211647.png]]
this is data persistence/integrity issue.
##### Case 4
![[Pasted image 20261117211840.png]]
leader dies and follow is now leader.
if original leader comes back => problem have 2 leader.
![[Pasted image 20261117211933.png]]
problem => split brain that is 2 leader.
now 2 leader where to write(as will write to leader only) and who to ask for update 2 brain in the network.
follow will get confused if have multiple leaders.
will be data integrity issue.
##### Obs
There is no guarantee as everything asynchronous can't say for sure.
need Distributed consensus(agreement).
all follow should agree on who is leader weather he is down, what is order of selecting leader and what to do when the down leader comes back.
need to make sure all nodes are on same page.
### Conclusion
1. Simpler easy to modify existing back-end to add replicas
2. Easy fix if follower nodes fail
3. More read throughput
But, for more write throughput need to use some other technique.
Downside => leader goes down have complexity.
