## Leaderless replication
It is uses in 
1. Cassandra (open source)
2. Riak (open source)
3. Dynamo DB  => not sure
### working
way to make sure value in each replica is up-to-date
#### Read repair
Kate is going to write Jordan = cute to many DB
all DB has version 20: Jordan = ugly
![[Pasted image 20261123183643.png]]
a reader will resolve read conflict by choosing the latest version reads.
replica will update after this read called as `read repair`.
![[Pasted image 20261123184310.png]]
other way of knowing value are updated
#### Anti-entropy
Propagate changes in the background.
processing writes a,b,c,d,e,f,g
![[Pasted image 20261123184548.png]]
not use replication log, only send writes which are not present in other nodes.
Problem: knowing diff of writes takes O(n) scan.
Use Merkle tree.
##### Merkle tree
![[Pasted image 20261123184840.png]]
a=10 -> key value pair row-1
b=45 -> key value pair row-2
steps
1. take hash of all row
2. take up sum all pair of hashes and take hash, repeat
till get final node.
this tree can be compared to quickly tell diff between 2 nodes.
![[Pasted image 20261123185051.png]]
here comparison is O(`logn`).
compare start at root
- if same value stop(both nodes are same)
- else compare children => breadth first search
- go on the route of the when hash is different rout to reach the different write.
![[Pasted image 20261123185412.png]]
find final b value is different => send diff to the behind node to update it
![[Pasted image 20261123185526.png]]
it is like binary tree.
