#### PKCE
PKCE => proof key for code exchange.
before this spring boot generates a `code_verifier` string.
get it's SHA-256 name it `code_challenge` string.
![[Pasted image 20260916122249.png]]
when request authentication request set `code_challenge` with it.
google server remember the this `code_challenge` for this request.(all at `frontend`)
![[Pasted image 20260916122425.png]]
then, does normal login flow. 
at code and token exchange(all at `backend`) : will send `coder_verifier` and google will calculate it's SHA_256 and match it with `code_challenge` and if match then only give token.
due to single direction nature of hashing it makes sure only our application which created the request can get the token.
![[Pasted image 20260916122848.png]]
benefits
- hacker knows `code_challange` can't know `code_verifier` from it.
- thus, achieved security
