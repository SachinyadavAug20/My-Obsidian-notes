## 1. C++ String Basics & Mechanics

In C++, a `string` is a dynamic sequence of characters.

### Basic Input Behaviour (`cin`)

- `cin >> str;` behaves exactly like input for `int` or `char`—it **breaks at spaces or newlines (`'\n'`)**.
    
- **Example:** If the input is `"World Good"`, `cin >> str;` will store only the first word: `str = "World"`.
    

### String Concatenation & Comparisons

- **Concatenation (`+`):** Combines strings directly together.
    
    C++
    
    ```
    string str1 = "Hello", str2 = "world";
    string result = str1 + str2; // Output: "Helloworld"
    ```
    
- **Comparison (`==`):** Checks if two strings are identical character-by-character (**Case-Sensitive**).
    
    C++
    
    ```
    // "hello" != "Hello" due to case mismatch
    bool check = (str1 == str2); // Evaluates to false
    ```
    

## 2. Character Operations & Index Access

Strings can be treated like 0-indexed arrays of characters.

- **Index Access:** `str[index]` accesses the character at a specific position.
    
- **In-place Replacement:** `str[0] = 'a';` changes the first character of the string to `'a'`.
    

### The Critical Difference: `"a"` vs `'a'`

- `"a"` is a **String Literal**: Contains the character `'a'` plus an implicit null-terminating character `'\0'`.
    
- `'a'` is a **Character Literal**: A raw single byte storing the literal character values.
    
    $$\text{"a"} \neq \text{'a'}$$
    

### Core String Utility Methods

- `str.size()`: Returns the total number of characters (length) in the string.
    
- `str.push_back('a')`: Appends a character directly to the end of the string.
    
- `str.erase(pos, length)`: Deletes characters out of the string object.
    
    - `pos`: The starting index where deletion begins.
        
    - `length`: The exact number of characters to remove.
        

> [!danger] C++ Limitation Warning
> 
> There is **no native `str.toUpperCase()` method** in standard C++. To change case, you must perform a character-by-character transformation loop using the `toupper(char)` function.

## 3. Handling Complete Line Inputs: `cin` vs `getline`

To capture entire sentences with spaces, use `getline(cin, str1);` which consumes characters all the way up until it hits a newline (`'\n'`).

### Understanding the Input Buffer Trap

To avoid bugs, visualize how `cin` and `getline` read from the internal memory stream:

```
Input Buffer Layout: [ Token 1 ]  [ Space ]  [ Token 2 ]  [ \n ]
```

|**Feature**|**cin >>**|**getline(cin, str)**|
|---|---|---|
|**Step 1**|**Ignores** all leading `'\n'` and spaces|Starts reading **immediately** from where the cursor currently sits|
|**Step 2**|Captures the next valid alphanumeric block|Captures every character encountered|
|**Step 3**|**Stops right before** trailing spaces or `'\n'`|**Stops after consuming** the ending `'\n'`|

### The Buffer Bug & `cin.ignore()` Fix

Because `cin >>` leaves the trailing newline (`'\n'`) sitting raw in the stream buffer, a `getline` statement executed right after will immediately read that left-over `'\n'` as an empty line and stop.

- **The Fix:** Use `cin.ignore();` right after a traditional `cin` read. This clears out the single hanging character at the cursor position without saving it, clearing the track for your next `getline`.


```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int x;
    string s;
    
    cin >> x;        // Leaves '\n' in the input buffer
    cin.ignore();    // Clears the '\n' from the buffer
    
    getline(cin, s); // Works perfectly now!
}
```

## 4. Competitive Programming Trick: Palindromes

- A string is a **Palindrome** if it reads identically forwards and backwards.
    
- _Example:_ `"aba"` $\rightarrow$ reversed matches `"aba"`.
    

## 5. Working with "Big Numbers"

In competitive programming, you will often encounter integers so huge that they exceed normal scalar memory registers.

- **`long long int` Maximum Limit:** $\approx 10^{18}$
    
- **The String Solution:** When a problem introduces input numbers containing hundreds of digits (e.g., $10^{100}$), **always read and store the input as a `string`**. You can then safely manipulate individual digits one index position at a time without triggering memory variable overflows.
