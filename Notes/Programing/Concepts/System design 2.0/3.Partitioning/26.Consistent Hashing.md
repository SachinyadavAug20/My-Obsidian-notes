## Consistent hashing
it has pros:
1. Distributes keys evenly
2. Minimal data sent over the network on re-balance
3. Great for partitioning and load balancing
need to avoid load-balancing anyway.

### Total fixed number partition
![[Pasted image 20261128183650.png]]
it is persistent(entire backed has 12 partition) => no of nodes will change and adjust it.
if 2 nodes => 12 partition divided as 6 partition
if 4 nodes => 12 partition divides as 3 partition
pros
- it is simple to think about and easy to handle.
cons
- need to choose a good number(big number as can't give fraction of a partition to a node)
- too few -> our partitions get too big for the database
- too few -> overhead on disk of storing partitions
