## Container
Container is a way to package application with all the necessary dependencies and configuration.
that package is portable artifact shared and moved around.
makes development and deployment simpler due to thus properties.

## Application development
### Before container
if people working on same project need to install same dependence on each member machine(OS).
ex: making JS application need a DB(PostgreSQL and Redis(for messaging)) => of specific version.
each developer need to config it.
things can go wrong in doing(as there are many step if complex application) so,
![[Pasted image 20261123204424.png]]
### With container
no need to install anything on your OS.
because container is it's own OS(Linux based) packaged with config and programs(with specific version).
and start scripts.
![[Pasted image 20261123204936.png]]
packages with all needed configuration.
download step => simple docker command(fetches the container and runs it).`docker run postgres`
if 10 dependencies => need to do 10 such commands.

> [!NOTE]
> Pros: can have different version of same program on local environment without any conflict with docker container as it is isolated

## Application Deployment
### Before container
Developer will produce the artifices and instruction on how to configure those artifices.
developer give those artifices to operation team to setup environment deploy it.
![[Pasted image 20261123205550.png]]
Problem as need to do OS.
![[Pasted image 20261123205722.png]]
miss understanding/communication between developer and operation.
### With container
developer and operation team to package application in container.
as it is configured for the container(that is an environment) no need to configure for server just run the docker container on server.
need to install docker on server first to pull and run the containers.
![[Pasted image 20261123210450.png]]
Kubernetes offers a more abstracted solution for deployment of multiple containers.
