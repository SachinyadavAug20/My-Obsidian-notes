## RAG(Retrieval Augmented Generation)
Will make a E-commerce chat bot.
need to give system prompt -> store in vector DB.
make vector of the query => ![[Pasted image 20261018104619.png]]
will have PDF file for policies.![[Pasted image 20261018113404.png]]
will find vector of all this files and do similarity search using vector of query on this policies.
similarly result will given to LLM => so, LLM only get context of what is need instead of everything.
![[Pasted image 20261018114237.png]]
fill give only relevant data in context.
![[Pasted image 20261018114312.png]]
This is called as RAG mode => retrieval(similarity content fetched) augmentation(give only relevant context to the LLM) generation(LLM generates response) => RAG.
#### RAG concept
This is RAG => it uses vector to give LLM only the necessary context instead of giving all of it for a particular query.
basic concept is give only the needed context to answer the query.
in vector DB also when search will use `IVF` or `HNSM` => fast search in the context and give only relevant context.
#### Convert PDF to vector
can't make 1 vector of 1 PDF => as it will lost semantic.
need to be able to cherry pick some part of all PDF which is relevant to our query in hand.
take first 1000 words and make vector.
1 document = many(100) vectors.
![[Pasted image 20261018123944.png]]
will use Vector DB => `Pinecone`.
thus, now LLM has long term memory and RAG will help to retrieve only the relevant context(using vector embedding and comparison) from the history instead of full context.
long term memory as history and vectors in DB.
