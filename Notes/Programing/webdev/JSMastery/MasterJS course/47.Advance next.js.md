## React server component (RSC)
Previously react runs on the client side. many JS bundle and client make HTML page -> client execute JS bundle -> bad performance on low-end devices, and bad SEO(as web crawler don't understand JS)
NextJS handle this problem using SSR -> send HTML to client to hydrate -> interaction component are on client side(event-listener and state are send as JS bundle) -> static DOM revived by server is compared to virtual DOM created by the JS bundle and placeholder are filled this process is called hydration -> if fail to match give hydration error

in nextJS :- when server send JS bundle the client has to wait till the full page is loaded and the page is ready.If to much interaction then it will be take too long to load the page.
this is solved by RSC, it's properties :-
- Is fresh component, which is exclusively run on server not even hydrated on client -> client only gets HTML(little JS)
- lead to faster page loading selective hydration and enhanced experience and UX and DX
###### working of RSC
- it is exclusively a react feature
- it is not tied to nextJS(any framework).recommended way is nextJS
- in nextJS every component is by default server component -> server give .rsc file(Server side representation of DOM) -> it makes tree virtual DOM to tell what to do to make html page

###### streaming: send parts of data piece by piece to the client and client joins the pieces and caches it. like video,music streaming. (user don't have to wait for all it to come together) use it by `renderToNodeStream` instead of `renderToString`
###### Selective hydration -> with streaming which piece arrived will be hydrated selectively(like learn and use don't wait till all learning is done start piece-by-piece)
It will start to hydrate as soon as there is something to hydrate
###### done using `Suspense` ![[Pasted image 20260525133313.png|146]] wrap what-ever will take long in `<Suspense></Suspense>`
```tsx
import {Suspense} from "react";

<Suspense fallback={<p>Loading...</p>}>
	<SomeTimeConsumingComponent/>
</Suspense>
```
###### working of `Suspence`
- when it faces Suspense  it will do it other thing and sent the loading to client and keep processing the component in Suspended component and stream the response to when prepared
