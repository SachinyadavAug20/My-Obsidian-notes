## 2. Conditional Branching (`if-else` Execution Flow)

When using an `if-else if-else` ladder, execution is optimized via short-circuiting:

* **Rule:** If a condition evaluates to **true**, the code block below it executes, and **the rest of the entire ladder below it is not checked**.

```cpp
#include <iostream>
using namespace std;

int main() {
    int number = 15;
    
    if (number > 10) {
        // This is true, so this block executes.
    } 
    else if (number > 5) {
        // This is completely SKIPPED/NOT CHECKED even though 15 > 5.
    } 
    else {
        // Skipped
    }
}

```

## 3. Variable Scope & Block Dynamics (`{ }`)

A variable's lifetime and visibility are tightly bound to the block `{}` in which it is declared.

### Local Scope Validation

A variable declared inside an outer block is accessible by nested inner blocks:

```cpp
#include <iostream>
using namespace std;

int main() {
    int x = 5; // Has local scope in main
    
    if (1) { 
        cout << x; // Valid! Works perfectly because it's inside the outer scope.
    }
}

```

### The Scope Compilation Error (Common CP Trap)

A variable declared *inside* a specific conditional block or loop block cannot be accessed outside of it:

```cpp
#include <iostream>
using namespace std;

int main() {
    int n = 4;
    
    if (n % 2 == 0) { 
        int x = 2; // x is declared inside the local if-block scope
    }
    
    cout << x; // ERROR! 'x' was not declared in this scope.
}

```

### Arbitrary Standalone Blocks

You can create a standalone new scope anywhere using raw curly braces `{}`.

* **Rule:** Inner scopes can access variables declared **outside** or **above** them, but the outer scope cannot look inside.

```cpp
#include <iostream>
using namespace std;

int main() {
    int outer_var = 10;
    
    { // New standalone scope starts
        int inner_var = 20;
        cout << outer_var; // Valid: Can access variables from outside the scope
    } // New standalone scope ends
    
    // cout << inner_var; // This would cause a compilation error
}

```

## 5. Jump Statements

Jump statements **act specifically on the current loop** in which they are physically placed.

* `break;` $\rightarrow$ Completely exits and **skips the entire loop** immediately (it does *not* just skip a block; it terminates the loop structure).
* `continue;` $\rightarrow$ Breaks the current execution path and **skips the current iteration**, jumping straight to the next loop pass evaluation.

## 6. Competitive Programming Math Trick: Extracting Digits

An incredibly frequent operation in array, string, and number-based DSA problems:

* **Find the Last Digit:** You can isolate the final digit of any base-10 number `n` by evaluating:

$$n \% 10$$



*Example:* For $123$, $123 \% 10 = \mathbf{3}$.
* **Find the Last $n$ Digits:** To isolate the trailing $n$ digits of a number, calculate the modulus against $10^n$:

$$n \% 10^n$$
