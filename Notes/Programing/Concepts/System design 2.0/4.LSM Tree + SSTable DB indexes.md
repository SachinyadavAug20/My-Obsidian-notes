## LSM(log-structured merge-tree)
it is a balanced binary search tree => like red-black tree, b-tree, ab tree or AVL tree.
![[Pasted image 20261105183017.png]]
student and marks ![[Pasted image 20261105183048.png]]
as it is binary tree => left(small) and right(big) rules followed.
write is O(`logn`) as need to find position first.
but, it is stored memory(not durable but can us WAL, also size constrain).
solution for LSM tree is 
- If LSM tree becomes too big then, 
	- Reset it, and save it to a SStable on disk
	-  ![[Pasted image 20261105184436.png]] SStable is immutable once created in memory
	- sort is simple as in-order traversal and sort in O(n) and save it as SStable.
	  ![[Pasted image 20261105184644.png]]
	- when, writing will write in memory LSM tree, but when reading to search in LSM tree and SStable.
		- Search in LSM tree -> O(`logn`) if not found then,
		- Search in most recent SStable(as will have most updated value(as can't change SStable so need to write again to update)) -> O(`logn`) as SStable is sorted
		- to delete -> do a tombstone value as marker value that it is deleted(like a boolean `isDeleted`)
	- thus, read and write is O(`logn`).
