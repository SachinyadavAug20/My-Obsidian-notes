### problem with hash map
1. Hash map are bad on disk
	- it is stored distributed evenly ![[Pasted image 20261104121359.png]]
	- thus, pointer has to move at many places.
	- thus, hash index are generally keep in memory(as it is electrical and no moving)
		- problem => RAM(do random access) is expensive => less capacity.
		- RAM is not durable(loss data) and not permanent.
			- fix it using write ahead log(`WAL`) => list of all changes and updates to the database => sequential writes in hard-disk for have durability.(If RAM erased run the `WAL` and get everything back(repopulate hash index using it))
			- `WAL` it will slow down as disk writes are slower.
	![[Pasted image 20261104122402.png]]
2. Can't do range query 
	- Hash map is good for specific index element, can't do all rows with name between A and B.
	- ![[Pasted image 20261104125217.png]]
	- will be O(n) or check all possibilities(might be endless)
	- can use things like Binary search tree => can do range query easily -> as ![[Pasted image 20261104125355.png]]
#### Pros of Hash index
- O(1) reads and writes
#### Cons of Hash index
- Keys must fit in memory
- No range queries
