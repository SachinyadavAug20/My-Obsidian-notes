code less reusable and SOLID principle breaks.
fix it using bridge design pattern.
## Bridge design solution
break a concept into 2 parts:
- high level part => abstraction(bird eye view)
	- ex: car type
- low level part => implementation(close up view)
	- ex: car engine
![[Pasted image 20261031162937.png]]
will make different abstraction and different implementation and part up
![[Pasted image 20261031163125.png]]
will have various car and engines
![[Pasted image 20261031164121.png]]
don't confuse in abstract(car) and abstract class and implementation(engine) and concrete class.
high level has a reference of low level.
![[Pasted image 20261031164304.png]]
can pass any engine in car.
thus, cover all possibility avoided class explosion.
only made m+n class instead of m\*n classes.

this is called bridge because composition acts as bridge between high level and low level

## Standard definition
Define: Bridge decouples an abstractions from its implementation, so that both can vary independently.
- Abstraction: High level layer(car)
- Implementation: Low level layer(engine)
## Code
```cpp
#include <iostream>
#include <string>

using namespace std;

// Implementation Hierarchy: Engine interface (LLL)
class Engine {
public:
    virtual void start() = 0;
    virtual ~Engine() {}
};

// Concrete Implementors (LLL)
class PetrolEngine : public Engine {
public:
    void start() override {
        cout << "Petrol engine starting with ignition!" << endl;
    }
};

class DieselEngine : public Engine {
public:
    void start() override {
        cout << "Diesel engine roaring to life!" << endl;
    }
};

class ElectricEngine : public Engine {
public:
    void start() override {
        cout << "Electric engine powering up silently!" << endl;
    }
};

// Abstraction Hierarchy: Car (HLL)
class Car {
protected:
    Engine* engine;
public:
    Car(Engine* e) {
        engine = e;
    }
    virtual void drive() = 0;
};

// Refined Abstraction: Sedan
class Sedan : public Car {
public:
    Sedan(Engine* e) : Car(e) {}

    void drive() override {
        engine->start();
        cout << "Driving a Sedan on the highway." << endl;
    }
};

// Refined Abstraction: SUV
class SUV : public Car {
public:
    SUV(Engine* e) : Car(e) {}

    void drive() override {
        engine->start();
        cout << "Driving an SUV off-road." << endl;
    }
};

int main() {
    // Create Engine implementations on the heap
    Engine* petrolEng = new PetrolEngine();
    Engine* dieselEng = new DieselEngine();
    Engine* electricEng = new ElectricEngine();

    // Create Car abstractions, injecting Engine implementations
    Car* mySedan = new Sedan(petrolEng);
    Car* mySUV = new SUV(electricEng);
    Car* yourSUV = new SUV(dieselEng); // electric

    // Use the cars
    mySedan->drive();   // Petrol engine + Sedan
    mySUV->drive();     // Electric engine + SUV
    yourSUV->drive();   // Diesel engine + SUV

    // Clean up
    delete mySedan;
    delete mySUV;
    delete yourSUV;

    return 0;
}
```

## Difference between Strategy and bridge
is choosing engine is different engine strategies ??
![[Pasted image 20261031170010.png]]
car is client of engine and client has a strategy.
difference is 
- Design pattern are to make code clean => tightly coupled --> loss-ly coupled
- thus, some design pattern look same
- difference is in `intent` => what is the intent of code
- Strategy => have different algorithm to be choose by the client.(dynamically change algorithm)
- Bridge => high level and low level connection, can work independently vary.(once selected 1 engine don't change it dynamically) no indention to change again and again.
  have more abstract(client in strategy)
