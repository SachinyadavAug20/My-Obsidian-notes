#### `@SpringBootApplication`
- has many annotation used internally => configuration![[Pasted image 20260713182504.png]]![[Pasted image 20260713182741.png]]
- can make more config files but spring declares main config file.
- main class is also a config file can make beans in it.
- Thus it scans for `@Component` class to handle.
```java
@SpringBootApplication
public class SpringBootCoreApplication {
    public static void main(String[] args) {
        ApplicationContext context=SpringApplication.run(SpringBootCoreApplication.class, args);
        OrderService os=context.getBean(OrderService.class);
        os.processOrder();
        UserService us=context.getBean(UserService.class);
    }
    @Bean
    public UserService getUserService(){
        return new UserService();
    }
}
```
conventions of spring boot(opinionated frame work)
- component scan happens in the package in which main(spring application class) class is present. can base it `@SpringBootApplication(scanBasePackage="in.strikes")`
- similarly can change config which you don't agree to by passing value for key.
#### `@EnableAutoConfiguration`
see project and create all important beans based on current project structure.
"Look at my project and create any beans seem important to you."
same methods
- `@Component` -> to make bean of a class
- `@Bean` -> to make a method bean
there is a third way
- `@AutoConfiguration` -> it used internally by spring boot. for special class made by spring boot inside it make beans.
for this third way to work need to enable it using this config `@EnableAutoConfiguration`.
similarly can make more beans
```java
@SpringBootApplication
public class SpringBootCoreApplication {
    public static void main(String[] args) {
        ApplicationContext context=SpringApplication.run(SpringBootCoreApplication.class, args);
        OrderService os=context.getBean(OrderService.class);
        os.processOrder();
        UserService us=context.getBean(UserService.class);
    }
    @Bean
    public UserService getUserService(){
        return new UserService();
    }
    @Bean
    public JsonParser getJsonParser(){
        return new BasicJsonParser();
    }
}
```
generally will do it for own jar instead of `JsonParser`
all external library jar file bean are not created directly then,
- if spring need some from it(if have many dependency)
- show to connect many classes need to do many manual config
- spring has some classes to manage this dependency. which will get this `@AutoConfiguration`
- example can get use of web starter => to make 
```xml
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
```
at run it will start a server at `Tomcat initialized with port 8080 (http)`
will have some class whose being in IOC is important thus, it will be handle by spring using `@AutoConfiguration`.
thus background works -> starts server.
- It is written in spring for web(standard library) OR
- if other dependency they may also have it(non-standard).
```java
@AutoConfiguration
@ConditionalOnClass(getWebA.class)
class A{
	@Bean
	@ConditionalOnMissingBean // create if not already exist
	public WebClassA getwebclassA(){
		return new WebClassA();
	}
}
```
will make bean if condition class exists in dependency.
will have auto config by using this annotation.

make a class
```java
package com.example.app;

import org.springframework.stereotype.Component;

@Component
public class PaymentGetWay {
    private String type;
    private int retryCount;
    public void setType(String type) {
        this.type = type;
    }
    public String getType() {
        return type;
    }
    public void setRetryCount(int retryCount) {
        this.retryCount = retryCount;
    }
    public int getRetryCount() {
        return retryCount;
    }
}
```
need to access bean to use this get way.
can do 
```java
@SpringBootApplication
public class AppApplication {
    public static void main(String[] args) {
        ApplicationContext context = SpringApplication.run(AppApplication.class, args);
        PaymentGetWay paymentGetWay = context.getBean(PaymentGetWay.class);
        paymentGetWay.setType("Paytm");
        paymentGetWay.setRetryCount(10);
        System.out.println(paymentGetWay.getType());        // Paytm
        System.out.println(paymentGetWay.getRetryCount());  // 10
    }
}
```
but, if need this property to set by application.properties.
```properties
paymentGetWay.retryCount=10
PaymentGetWay.type=Paytm
```
in class to accept it
```java
@Component
public class PaymentGetWay {
    private String type;
    private int retryCount;
    PaymentGetWay(@Value("${PaymentGetWay.type}") String type,@Value("${paymentGetWay.retryCount}") int retryCount) {
        this.type = type;
        this.retryCount = retryCount;
    }
    public String getType() {
        return type;
    }
    public int getRetryCount() {
        return retryCount;
    }
}
```

##### `@ConfigurationProperties`
this class will get all it's properties from config file.
```java
@Component
@ConfigurationProperties("payment-properties") // prefix to search
public class PaymentProperties {
    private String type;
    private int retryCount;
    private boolean enabled;
    private int timeOut;
    public void setType(String type) {
        this.type = type;
    }
    public void setRetryCount(int retryCount) {
        this.retryCount = retryCount;
    }
    public void setEnabled(boolean enabled) {
        this.enabled = enabled;
    }
    public void setTimeOut(int timeOut) {
        this.timeOut = timeOut;
    }
    public String getType() {
        return type;
    }
    public int getRetryCount() {
        return retryCount;
    }
    public boolean getIsEnable() {
        return enabled;
    }
    public int getTimeOut() {
        return timeOut;
    }
}
```
in config file
```properties
payment-properties.type=RazorPay
payment-properties.retryCount=8
payment-properties.timeout=300
payment-properties.enabled=true
```
need to be in canonical form and need getter and setter for each field for it.
get all this properties in payment get way
- pattern is make a properties file and inject it in some class to use this properties
```java
@Component
public class PaymentGetWay {
    private PaymentProperties properties;
    public PaymentGetWay(PaymentProperties properties) {
        this.properties = properties;
    }
    public String getType() {
        return properties.getType();
    }
    public int getRetryCount() {
        return properties.getRetryCount();
    }
	public void print() {
        System.out.println(this.getType());    
        System.out.println(this.getRetryCount());  
    }
}
```
can do canonical in config it will convert to camel case for java code(it is flexible).
need to do in main without interaction with IOC directly
```java
    public static void main(String[] args) {
        ApplicationContext context = SpringApplication.run(AppApplication.class, args);
        PaymentGetWay paymentGetWay = context.getBean(PaymentGetWay.class);
        paymentGetWay.print();
    }
```
can do better -> need to run this method in start.
need to use application runner.
```java
package com.example.app;

import org.springframework.boot.ApplicationArguments;
import org.springframework.boot.ApplicationRunner;
import org.springframework.stereotype.Component;

@Component
public class DemoRunner implements ApplicationRunner{
    private PaymentGetWay pgw;
    public DemoRunner(PaymentGetWay pgw){
        this.pgw=pgw;
    }
    @Override
    public void run(ApplicationArguments args) throws Exception{
        // args are command line args (advance version)
        pgw.print();
    }
}

// main
    public static void main(String[] args) {
        SpringApplication.run(AppApplication.class, args);
    }
```
now no need to get context and interact with IOC.
can also use `CommandLineRunner` => have method 
`void run(String ...args)` => variable arguments(0 or many args).
