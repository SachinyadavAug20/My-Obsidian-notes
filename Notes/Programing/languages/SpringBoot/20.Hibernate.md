    @Override
    public Boolean convertToEntityAttribute(String value) {
        if(value==null) return null;
        return value=="Yes";
    }
    @Override
    public String convertToDatabaseColumn(Boolean value) {

        return value? "Yes" : "No";

##### Flush
It does make sure persistance context and DB is at same page(i.e persistence context is write behind) 
when in update do
```java
    @Transactional
    public Student updateUser(Student student, Long id) {
        Student s1 = studentRepository.getUserById(id);
        if (s1 == null) throw new RuntimeException("User not found");
        s1.setName(student.getName());
        s1.setAge(student.getAge());
        s1.setEmail(student.getEmail());
        return s1;
    }
```
it don't do 3 update query it update all 3 in 1 query.
because, it check when flush, check changes(changed entity is called dirty entity) in heap and DB object and does the update.
can do flush many times to make it do update query for each change.
```java
// in repo
    public void flush() {
        entityManager.flush();
    }
// in service
    @Transactional
    public Student updateUser(Student student, Long id) {
        Student s1 = studentRepository.getUserById(id);
        if (s1 == null) throw new RuntimeException("User not found");
        s1.setName(student.getName());
        studentRepository.flush();
        s1.setAge(student.getAge());
        studentRepository.flush();
        s1.setEmail(student.getEmail());
        studentRepository.flush();
        return s1;
    }
```
![[Pasted image 20260816142155.png]]
practial use of flush
- batch processing save all students
- will try to process 1 batch and save it.
- not wait for all to be ready and hit the DB together
```java
    public void saveAll(List<Student> students) {
        for(Student s:students){
            entityManager.persist(s);
        }
    }
```
problem -> millions of object in peristance context, lead to overflow.(slow down)
make group of 1000 then flush it.
```java
    public void saveAll(List<Student> students) {
        int ctn=0;
        for(Student s:students){
            entityManager.persist(s);
            ctn++;
            if(ctn%100==0){
                entityManager.clear();
                entityManager.flush();
            }
        }
    }
```
we know perist -> keep it in context and when flush remove it from context and put in DB.
This batch processing -> good for backend(server) program and also good for DB.
This persistant context -> L1(first level cache).
