## 1. Character Case Conversion Logic

To convert characters between uppercase and lowercase manually without built-in libraries, use their relative distance on the ASCII table.

- **The Core Intuition:** The structural offset distance between any lowercase character and its corresponding uppercase character is constant ($n$).
    
    $$\text{'a'} - \text{'x'} = \text{'A'} - \text{'X'}$$
    
- **The Formula:** To find the capital version of a lowercase character variable $x$:
    $$\text{'X'} = \text{'A'} + (x - \text{'a'})$$

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    char small = 'g';
    // Shifts the relative distance from 'a' into the 'A' range
    char capital = 'A' + (small - 'a'); 
    cout << capital; // Output: G
    return 0;
}
```

## 2. Binary to Decimal Conversion (Optimized)

### Approach A: Standard Positional Expansion (Power Method)

Multiply each bit by its corresponding power of 2, reading from **Right to Left**.

- **Example for $1010_2$:**
    
    $$1010_2 \implies (1 \times 2^3) + (0 \times 2^2) + (1 \times 2^1) + (0 \times 2^0) = 8 + 0 + 2 + 0 = \mathbf{10}$$
    

### Approach B: Linear Horner’s Method (Without `pow()`)

When working with input streams or string inputs, computing powers can be slow or overflow. Instead, process from **Left to Right**, maintaining a running total that doubles with each iteration.

- **The Structural Property:**
- $$1011_2 \implies 1 \times 2^3 + 0 \times 2^2 + 1 \times 2^1 + 1 \times 2^0$$ $$\implies ((1 \times 2 + 0) \times 2 + 1) \times 2 + 1$$ 
- **The Algorithm Workflow:**
```cpp
Start with: ans = 0
For each bit from Left to Right:
    ans = (ans * 2) + current_bit
```

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    string binary = "1011"; // Equivalent to decimal 11
    int ans = 0;
    
    for(int i = 0; i < binary.size(); i++) {
        int current_bit = binary[i] - '0'; // Convert char to int
        ans = (ans * 2) + current_bit;
    }
    
    cout << ans; // Output: 11
    return 0;
}
```

## 3. Combinatorics: Pascal’s Triangle & $^nC_r$ Optimization

To evaluate combinations ($^nC_r$), the standard factorial formula can easily trigger integer overflows even for relatively small values of $n$:

$$^nC_r = \frac{n!}{r!(n-r)!}$$

### Pascal's Triangle Representation

Combinations map perfectly to rows and columns of Pascal's Triangle:

```cpp
          °C₀
       ¹C₀    ¹C₁
    ²C₀    ²C₁    ²C₂
 ³C₀    ³C₁    ³C₂    ³C₃
```

### The Optimized Iterative Multiplier Method

To prevent intermediate multiplication products from causing an overflow, evaluate $^nC_r$ iteratively from its preceding term $^nC_{r-1}$.

- **The Recurrence Formula:**
$$^nC_r = {^nC_{r-1}} \times \frac{n - r + 1}{r}$$
- **Base Case Implementation Rule:**
    $$C(n, 0) = 1$$

```cpp
#include <bits/stdc++.h>
using namespace std;

// Computes nCr lineally in O(r) time with reduced overflow risk
long long computeNCR(int n, int r) {
    if (r > n) return 0;
    if (r == 0 || r == n) return 1;
    
    // Optimization property: nCr is identical to nC(n-r)
    if (r > n - r) r = n - r; 
    
    long long ans = 1;
    for (int i = 1; i <= r; i++) {
        // Multiplies by (n - i + 1) and divides by i concurrently
        ans = ans * (n - i + 1) / i; 
    }
    return ans;
}

int main() {
    cout << computeNCR(5, 2); // Output: 10
    return 0;
}
```
