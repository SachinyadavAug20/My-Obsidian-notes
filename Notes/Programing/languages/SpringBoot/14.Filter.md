### Filters
Filtering happens before dispatcher servlet ![[Pasted image 20260801093834.png]]
thus, filter don't get request object and not decided the endpoint where request is going to land.
Filters are commonly used for 
- logging request/response
- security check -> authentication header check
- request/response modify.
- encoding (`UTF-8`)
filter can 
- inspect the request
- inspect headers
- inspect cookies
- check authentication information
- add response headers
- modify request or response wrappers
- block the request
- allow the request to continue
- log request details
- measure total request duration
can also see request which will never reach dispatcher servlet. -> like `static/logo.png`,`/error`,`favicon.ico`.

##### Filter for authentication
will auth by a rule -> like request must contain a special key in header.![[Pasted image 20260801113758.png]]
value -> is encrypted and token is made.
will see if header has token 123 -> then only pass this request else don't.
```java
@Component
public class AuthenticationFilter implements Filter{
    @Override
    public void doFilter(ServletRequest request,ServletResponse response,FilterChain chain) throws IOException,ServletException{
        HttpServletRequest httpRequest = (HttpServletRequest) request;
        HttpServletResponse httpResponse = (HttpServletResponse) response;
        String token = httpRequest.getHeader("token");
        if(token == null || !token.equals("123")){
            // httpResponse.setStatus(401); OR
            httpResponse.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            return; // go back to client
        }else{
            chain.doFilter(request, response);
        }
    }
}
```

##### RequestId
create requestId for each request and attach that id with it's response.
> [!Attention] Chain
> When made multiple filter only 1 filter can be starting point which has `@Component` so spring handles it then, rest all filter will be called using the `chain.doFilter()`.Don't make all `@Component`.

```java
@Component
public class LoggingFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request,
            ServletResponse response,
            FilterChain chain) throws IOException, ServletException {
        HttpServletRequest httpRequest = (HttpServletRequest) request;
        HttpServletResponse httpResponse = (HttpServletResponse) response;
        String requestId = UUID.randomUUID().toString();
        httpResponse.setHeader("X-Request-ID", requestId);
        System.out.println("Incoming request from: " + 
                            httpRequest.getMethod() + " on " +
                            httpRequest.getRequestURI());
        chain.doFilter(request, response);
        System.out.println("Outgoing response with status code: " +
                            httpResponse.getStatus());
    }
}
```

##### Error response
give like `api key` or else won't authorize the client.
headers are case in-sensitive -> `X-API-key` = `x-api-key`.
```java
@Component
public class AuthenticationFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request,ServletResponse response,FilterChain chain) throws IOException,ServletException{
        HttpServletRequest httpRequest = (HttpServletRequest) request;
        HttpServletResponse httpResponse = (HttpServletResponse) response;
        String token = httpRequest.getHeader("token");
        String apiKey = httpRequest.getHeader("x-api-key");
        if(token == null || !token.equals("123")){
            httpResponse.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            return;
        }else if(apiKey == null || !apiKey.equals("secret123")){
            httpResponse.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            httpResponse.setContentType("application/json");
            httpResponse.getWriter().write(
                    "\n{\"message\":\"Invalid or missing API key\"}"
                    );
            return;
        }
        chain.doFilter(request, response);
    }
}
```

why not change response after `chain.doFilter(...)` ??
- Because in downstream call the response is committed and final, BECAUSE as dispatcher servlet has made the response using `ServletResponse` thus changing object will not effect response which is already created by dispatcher servlet.
- thus will not work.
edit status code and body of response.

```java
            res.setStatus(401);
```
